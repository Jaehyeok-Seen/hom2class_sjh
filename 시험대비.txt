## 📝 과목평가 범위 정답

### [MLP - 6문제]

**1번 정답:**
- MLP = Multi-Layer Perceptron (다층 퍼셉트론)
- 각 레이어는 **완전 연결(Fully Connected)** 방식으로 연결
- 이전 레이어의 모든 뉴런이 다음 레이어의 모든 뉴런과 연결됨

**2번 정답:**
- 활성화 함수가 없으면 여러 층을 쌓아도 **선형 변환의 조합**이 되어, 결국 하나의 선형 함수와 동일
- 비선형성(Non-linearity)을 추가하여 **복잡한 패턴**을 학습할 수 있게 함
- 활성화 함수가 없으면 XOR 같은 비선형 문제를 해결할 수 없음

**3번 정답:**
- **수식**: ReLU(x) = max(0, x)
- **장점**:
  1. 계산이 매우 간단하고 빠름 (0보다 큰지만 확인)
  2. Vanishing Gradient 문제를 완화 (양수 구간에서 gradient = 1)
  3. Sparse activation (음수는 모두 0으로 만들어 일부 뉴런만 활성화)

**4번 정답:**
- **정의**: 역전파 과정에서 gradient가 점점 작아져서 앞쪽 레이어의 weight가 거의 업데이트되지 않는 현상
- **발생 상황**: 
  - 깊은 네트워크에서 Sigmoid나 Tanh 같은 활성화 함수 사용 시
  - 이들 함수의 gradient가 0~1 사이이므로, 여러 층을 거치며 곱해지면 gradient가 0에 수렴

**5번 정답:**
- **Hidden layer 개수 증가** (깊이):
  - 더 추상적이고 계층적인 특징 학습 가능
  - 복잡한 함수를 효율적으로 표현
  - 하지만 학습이 어려워질 수 있음 (Vanishing gradient 등)
  
- **각 layer의 뉴런 수 증가** (폭):
  - 각 레벨에서 더 많은 특징을 동시에 학습
  - 파라미터 수가 급격히 증가
  - 일반적으로 깊이를 늘리는 것이 더 효율적

**6번 정답:**
- **최소 1개의 hidden layer 필요**
- **이유**: 
  - XOR는 선형 분리 불가능한 문제
  - Hidden layer 없이는 선형 분류기만 만들 수 있음
  - 1개의 hidden layer로 입력 공간을 비선형 변환하여 선형 분리 가능한 공간으로 매핑
  - 예: 2개의 hidden neurons로 XOR 구현 가능

---

### [CNN - 6문제]

**7번 정답:**
- CNN = Convolutional Neural Network (합성곱 신경망)
- 주로 사용되는 데이터 타입: **이미지, 비디오** (2D/3D 격자 구조 데이터)

**8번 정답:**
- Filter(Kernel)는 **특징 추출기** 역할
- 입력 이미지를 슬라이딩하면서 특정 패턴(엣지, 코너, 질감 등)을 감지
- 학습을 통해 filter의 weight가 조정되어 유용한 특징을 자동으로 학습

**9번 정답:**
- **목적**:
  1. 공간적 크기 축소 (Dimensionality reduction)
  2. 계산량과 파라미터 수 감소
  3. 위치 변화에 대한 불변성(Translation invariance) 제공
  4. Overfitting 방지

- **대표적인 방법**:
  1. **Max Pooling**: 영역 내 최댓값 선택
  2. **Average Pooling**: 영역 내 평균값 계산

**10번 정답:**
- **출력 크기 공식**: [(입력 크기 - 필터 크기 + 2×Padding) / Stride] + 1
- 계산: [(28 - 5 + 2×1) / 2] + 1 = [(28 - 5 + 2) / 2] + 1 = [25 / 2] + 1 = 12 + 1 = **13×13**

**11번 정답:**
- **Parameter 수 관점**:
  - MLP: 모든 픽셀이 독립적으로 연결 → 파라미터 수 폭발적 증가
  - CNN: Filter를 공유하며 재사용 → 파라미터 수 대폭 감소
  - 예: 28×28 이미지, 100개 hidden neurons
    - MLP: 784×100 = 78,400개 파라미터
    - CNN (5×5 filter, 10개): 5×5×10 = 250개 파라미터

- **Spatial locality 관점**:
  - 이미지에서 인접한 픽셀들은 서로 관련성이 높음 (지역성)
  - CNN은 local receptive field로 지역 패턴을 효과적으로 포착
  - MLP는 모든 픽셀을 flat하게 연결하여 공간 정보 손실

**12번 정답:**
- **해결하는 문제**: Degradation problem (네트워크가 깊어질수록 성능이 오히려 떨어지는 현상)
- **원리**:
  - Skip Connection으로 입력을 출력에 직접 더함: F(x) + x
  - Gradient가 skip connection을 통해 직접 전달되어 vanishing gradient 완화
  - 네트워크가 identity mapping(입력=출력)을 쉽게 학습 가능
  - "추가 학습할 것(residual)"만 학습하면 되므로 최적화가 쉬워짐

### [데이터 생성 방법 - 6문제]

**13번 정답:**
- **정의**: 기존 데이터에 변형을 가해 새로운 학습 데이터를 인위적으로 생성하는 기법
- **필요성**:
  1. 학습 데이터가 부족할 때 데이터셋 크기 확장
  2. Overfitting 방지 (다양한 변형으로 일반화 능력 향상)
  3. 모델의 robustness 증가 (다양한 상황에 대응)

**14번 정답:**
1. 회전(Rotation)
2. 좌우/상하 반전(Flip)
3. 크기 조정(Scaling/Zoom)
4. 이동(Translation)
5. 밝기/대비 조정
6. 노이즈 추가
7. 자르기(Cropping)
(3가지만 요구했으므로 이 중 3개면 정답)

**15번 정답:**
- **Oversampling**: 
  - 소수 클래스의 샘플을 복제하거나 생성하여 증가
  - 단점: 동일 샘플 반복으로 overfitting 위험

- **Undersampling**: 
  - 다수 클래스의 샘플을 제거하여 감소
  - 단점: 유용한 정보 손실 가능성

**16번 정답:**
- **기본 원리**:
  1. 소수 클래스의 한 샘플 선택
  2. 그 샘플의 k-nearest neighbors 중 하나를 무작위 선택
  3. 두 샘플 사이의 선형 보간으로 새로운 합성 샘플 생성
  4. 새로운 샘플 = 원본 + λ × (이웃 - 원본), 여기서 λ는 0~1 사이 난수
- 단순 복제가 아니라 새로운 샘플을 생성하여 overfitting 완화

**17번 정답:**
- **Generator (생성자)**:
  - 랜덤 노이즈에서 가짜 데이터를 생성
  - 실제 데이터와 구분되지 않는 데이터를 만들려고 시도

- **Discriminator (판별자)**:
  - 입력 데이터가 실제인지 가짜인지 판별
  - 실제와 가짜를 정확히 구분하려고 시도

- **학습 과정**:
  1. Generator가 가짜 데이터 생성
  2. Discriminator가 실제/가짜 구분 시도
  3. Generator는 Discriminator를 속이도록 학습
  4. Discriminator는 더 잘 구분하도록 학습
  5. 두 모델이 서로 경쟁하며 동시에 발전 (적대적 학습)
  6. 최종적으로 Generator가 매우 그럴듯한 데이터 생성 가능

**18번 정답:**
- Test set은 **실제 환경의 데이터를 대표**해야 함
- 증강된 데이터는 인위적인 변형이므로 실제 분포와 다를 수 있음
- 모델의 **실제 성능을 정확히 평가**하기 위해서는 원본 데이터로 테스트해야 함
- 증강을 적용하면 성능이 부풀려져 보일 수 있음 (실제보다 과대평가)
- Train/Validation set에만 증강을 적용하여 모델을 강건하게 만들고, Test set은 현실을 반영

### [토큰화와 임베딩 - 6문제]

**19번 정답:**
- **토큰화**: 텍스트를 작은 단위(토큰)로 분할하는 과정
- **기본적인 방법**:
  1. **Character-level**: 문자 단위로 분할 (예: "hello" → ['h','e','l','l','o'])
  2. **Word-level**: 단어 단위로 분할 (예: "hello world" → ['hello', 'world'])
  3. **Subword-level**: 단어의 부분 단위 (예: "unhappiness" → ['un', 'happiness'])

**20번 정답:**
- **임베딩**: 토큰을 고정된 크기의 **밀집 벡터(dense vector)**로 변환하는 과정
- **필요성**:
  1. 컴퓨터는 텍스트를 직접 처리할 수 없어 숫자로 변환 필요
  2. One-hot encoding은 차원이 너무 크고 sparse함
  3. 의미적 유사성을 벡터 공간에 표현 (유사한 단어는 가까운 벡터)
  4. 효율적인 계산과 일반화 가능

**21번 정답:**
- **기본 원리**:
  1. 텍스트를 character 단위로 시작
  2. 가장 빈번하게 등장하는 연속된 바이트(또는 character) 쌍을 찾음
  3. 해당 쌍을 하나의 새로운 토큰으로 병합
  4. 2-3 과정을 원하는 vocabulary 크기에 도달할 때까지 반복
- 예: "low", "lower", "lowest" → 'lo', 'w'가 자주 나오면 'low'로 병합

**22번 정답:**
- **CBOW (Continuous Bag of Words)**:
  - 주변 단어(context)로 중심 단어(target)를 예측
  - 입력: 주변 단어들, 출력: 중심 단어
  - 예: "I [love] machine learning" → 'I', 'machine', 'learning'으로 'love' 예측

- **Skip-gram**:
  - 중심 단어로 주변 단어들을 예측
  - 입력: 중심 단어, 출력: 주변 단어들
  - 예: "I [love] machine learning" → 'love'로 'I', 'machine', 'learning' 예측
  - 작은 데이터셋이나 희귀 단어에 더 효과적

**23번 정답:**
- **"I love machine learning"**

- **Character-level**:
  - 토큰: ['I', ' ', 'l', 'o', 'v', 'e', ' ', 'm', 'a', 'c', 'h', 'i', 'n', 'e', ' ', 'l', 'e', 'a', 'r', 'n', 'i', 'n', 'g']
  - 개수: 23개 (공백 포함)
  - 장점: OOV 문제 없음, vocabulary 크기 작음
  - 단점: 시퀀스가 매우 길어짐, 의미 단위를 직접 학습해야 함

- **Word-level**:
  - 토큰: ['I', 'love', 'machine', 'learning']
  - 개수: 4개
  - 장점: 의미 단위 보존, 시퀀스 짧음
  - 단점: Vocabulary 크기 폭발, OOV 문제 발생

**24번 정답:**
- **OOV 문제**: 학습 시 보지 못한 단어가 등장하면 처리 불가
- **해결 방식**:
  1. 단어를 subword 단위로 분해 (예: "unhappiness" → "un" + "happiness")
  2. Character는 모두 vocabulary에 있으므로, 어떤 단어도 알려진 subword들의 조합으로 표현 가능
  3. 새로운 단어도 기존 subword 조합으로 처리
  - 예: "ChatGPT"를 본 적 없어도 → "Chat" + "GP" + "T"로 표현 가능
- 단어와 character의 중간 단위로 **유연성**과 **의미 보존**을 동시에 달성

**25번 정답:**
- **메모리 효율성**: 전체 모델을 갱신하지 않고 소량의 파라미터만 학습하여 GPU 메모리 사용량 대폭 감소
- **학습 속도**: 학습할 파라미터가 적어 학습 시간 단축
- **배포 편의성**: 원본 모델 1개 + 작은 PEFT weight 여러 개로 다중 태스크 지원
- 이 중 가장 큰 장점은 **메모리 효율성**

**26번 정답:**
- **구조 변경하는 방법**: 
  - **Adapter layer** (원본 모델 내부에 새로운 레이어 추가)

- **구조 변경하지 않는 방법**: 
  - **Prompt tuning** (입력에 pseudo-token만 추가)
  - **LoRA** (기존 weight에 low-rank update만 추가, 추론 시 병합 가능)

**27번 정답:**
- **"Low-Rank"의 의미**: 큰 행렬을 두 개의 작은 행렬의 곱으로 근사
- **수식 예시**:
  - 원본 업데이트: ΔW (크기: d×d)
  - Low-rank 분해: ΔW ≈ A × B
    - A의 크기: d×r
    - B의 크기: r×d
    - 여기서 r << d (r은 rank, 매우 작은 값)
  
- **파라미터 수 비교**:
  - 직접 업데이트: d² 개
  - Low-rank: d×r + r×d = 2dr 개
  - 예: d=1000, r=8이면
    - 직접: 1,000,000개
    - Low-rank: 16,000개 (약 1/60)

**28번 정답:**
- **Trade-off**:

- **이득 (원본 4bit)**:
  - 메모리 사용량 대폭 감소 (1/4로 축소)
  - 대형 모델도 소비자급 GPU에서 실행 가능
  
- **손실 (원본 4bit)**:
  - 범용 성능 하락 불가피 (양자화 오차)
  - 원본 모델의 지식이 일부 손실

- **보상 (LoRA BF16)**:
  - 새로 학습하는 weight는 높은 정밀도 유지 → 학습 안정성
  - LoRA weight는 매우 적어서 BF16으로 유지해도 메모리 부담 작음
  - 목표 태스크에 대해서는 높은 성능 확보

- **최종 결과**: 극도로 제한된 메모리 환경에서도 특화 태스크에는 우수한 성능

**29번 정답:**
- **Full Fine-tuning**:
  - 메모리: 각 태스크마다 전체 모델 저장 필요 (10개 × 수백GB)
  - 배포: 태스크 전환 시 전체 모델 교체 필요
  - 유지보수: 각 모델을 독립적으로 관리, 버전 관리 복잡

- **PEFT**:
  - 메모리: 원본 모델 1개 + PEFT weights 10개 (각 수MB~수GB)
  - 배포: PEFT weight만 교체하여 즉시 전환
  - 유지보수: 원본 업데이트 시 모든 태스크에 자동 반영 가능

- **결론**: PEFT가 압도적으로 유리
  - 예: 70B 모델 기준
    - Full FT: 10개 × 140GB = 1.4TB
    - PEFT: 140GB + 10개 × 100MB = 141GB

**30번 정답:**
- **근본적인 이유**:
  1. **작용 범위의 제한**: Prompt tuning은 **입력 임베딩에만** 영향을 줌
     - 원본 모델의 모든 레이어는 고정
     - 입력 변형만으로 모델 행동을 조정해야 함
  
  2. **파라미터 수의 절대적 부족**: 
     - Prompt: 수십~수백 개 토큰 (수만 개 파라미터)
     - Adapter: 전체 레이어에 걸쳐 수백만 개 파라미터
     - LoRA: 핵심 weight matrix에 수백만 개 파라미터

  3. **간접적 제어**:
     - Adapter/LoRA: 모델의 계산 자체를 변경
     - Prompt: 입력을 "영리하게" 만들어 원하는 출력 유도
     - 복잡한 태스크일수록 간접 제어의 한계 명확

- **비유**: 
  - Prompt tuning = 건물 앞에서 안내 표지판만 바꾸기
  - LoRA/Adapter = 건물 내부 구조를 일부 수정하기

### [EDA - 5문제]

**31번 정답:**
- EDA = Exploratory Data Analysis (탐색적 데이터 분석)
- **주요 목적**:
  1. 데이터의 구조와 특성 파악
  2. 패턴, 이상치, 이상 현상 발견
  3. 가설 수립 및 검증
  4. 데이터 품질 문제 식별
  5. 적절한 모델링 전략 수립

**32번 정답:**
1. **삭제**: 결측치가 있는 행/열 제거
2. **대체(Imputation)**: 평균, 중앙값, 최빈값 등으로 채우기
3. **예측**: 다른 변수를 이용해 결측치 예측 (KNN, 회귀 등)
4. **별도 표시**: 결측 여부를 새로운 feature로 추가
5. **Forward/Backward fill**: 시계열 데이터에서 이전/다음 값으로 채우기
(3가지만 요구했으므로 이 중 3개면 정답)

**33번 정답:**
1. **IQR(Interquartile Range) 방법**:
   - IQR = Q3 - Q1
   - 이상치: Q1 - 1.5×IQR 미만 또는 Q3 + 1.5×IQR 초과

2. **Z-score 방법**:
   - Z = (x - 평균) / 표준편차
   - 일반적으로 |Z| > 3이면 이상치로 판단

3. **시각화 방법**:
   - Box plot으로 이상치 시각적 확인
   - Scatter plot으로 패턴에서 벗어난 점 확인

**34번 정답:**
1. **Histogram (히스토그램)**:
   - 수치형 변수의 분포 확인
   - 적합한 상황: 단일 변수의 빈도 분포, 정규성 확인

2. **Box plot (상자 그림)**:
   - 중앙값, 사분위수, 이상치 한눈에 파악
   - 적합한 상황: 그룹 간 분포 비교, 이상치 탐지

3. **Scatter plot (산점도)**:
   - 두 변수 간의 관계 시각화
   - 적합한 상황: 상관관계 확인, 패턴 발견

4. **Bar chart (막대 그래프)**:
   - 범주형 변수의 빈도
   - 적합한 상황: 카테고리별 개수/비율 비교

5. **Heatmap (열지도)**:
   - 상관계수 행렬 시각화
   - 적합한 상황: 다중 변수 간 상관관계 한눈에 파악

**35번 정답:**
- **이유**: 상관관계는 두 변수가 함께 변하는 패턴을 나타낼 뿐, 하나가 다른 하나를 **원인**으로 발생시킨다는 의미는 아님

- **예시**:
  1. **아이스크림 판매량과 익사 사고**: 
     - 높은 양의 상관관계 존재
     - 실제 원인: 기온 (더운 여름에 둘 다 증가)
     - 아이스크림이 익사를 유발하는 것은 아님

  2. **소방관 수와 화재 피해**:
     - 소방관이 많을수록 피해가 큼 (양의 상관)
     - 실제: 큰 화재일수록 소방관을 많이 투입
     - 인과관계는 반대 방향

- **핵심**: 제3의 변수(confounding variable)나 역인과관계 가능성 항상 고려해야 함

### [선형회귀 - 5문제]

**36번 정답:**
- **기본 수식**: y = β₀ + β₁x₁ + β₂x₂ + ... + βₙxₙ + ε

- **각 항의 의미**:
  - y: 종속변수 (예측하려는 값)
  - x₁, x₂, ..., xₙ: 독립변수 (feature)
  - β₀: 절편 (intercept) - x가 모두 0일 때 y의 값
  - β₁, β₂, ..., βₙ: 회귀계수 (각 feature의 영향력)
  - ε: 오차항 (모델이 설명하지 못하는 부분)

**37번 정답:**
- **MSE (Mean Squared Error)**:
  - 수식: MSE = (1/n) × Σ(실제값 - 예측값)²
  - 특징: 큰 오차에 더 큰 페널티 (제곱)
  - 이상치에 민감
  - 미분 가능하여 최적화에 유리

- **MAE (Mean Absolute Error)**:
  - 수식: MAE = (1/n) × Σ|실제값 - 예측값|
  - 특징: 모든 오차를 동등하게 취급
  - 이상치에 덜 민감 (robust)
  - 해석이 직관적 (평균적인 오차 크기)

- **선택 기준**: 
  - 이상치가 많으면 MAE
  - 큰 오차를 더 심각하게 여긴다면 MSE

**38번 정답:**
- **Overfitting**: 학습 데이터에는 매우 잘 맞지만, 새로운 데이터(test)에는 성능이 떨어지는 현상

- **방지 방법**:
  1. **정규화(Regularization)**: Ridge, Lasso 등으로 weight에 페널티 부여
  2. **Feature selection**: 불필요한 변수 제거
  3. **Cross-validation**: 여러 fold로 나누어 검증
  4. **더 많은 데이터 수집**: 학습 데이터 증가
  5. **Early stopping**: 검증 성능이 나빠지기 전에 학습 중단

**39번 정답:**
- **정규화 항**:
  - Ridge (L2): 손실함수에 Σβ² 추가 (계수의 제곱합)
  - Lasso (L1): 손실함수에 Σ|β| 추가 (계수의 절댓값 합)

- **Feature selection 관점**:
  - **Ridge**: 
    - 계수를 0에 가깝게 만들지만 정확히 0으로 만들지는 않음
    - 모든 feature를 유지하되 영향력 감소
    - Feature selection 효과 없음
  
  - **Lasso**: 
    - 일부 계수를 정확히 0으로 만듦
    - 자동으로 feature selection 수행
    - 중요하지 않은 변수 제거

- **언제 사용**: 
  - Ridge: 모든 feature가 어느 정도 관련 있을 때
  - Lasso: 일부 feature만 중요하고 나머지는 불필요할 때

**40번 정답:**
- **아니오, 항상 그런 것은 아님**

- **R²의 정의**: R² = 1 - (SSE/SST) 
  - 모델이 설명하는 분산의 비율
  - 0~1 사이 값 (1에 가까울수록 좋다고 알려짐)

- **반례**:
  1. **Overfitting**: 
     - 학습 데이터에서 R²=0.99로 매우 높음
     - 하지만 test 데이터에서는 성능 형편없음
     - 단순히 노이즈까지 학습한 결과

  2. **비선형 관계**: 
     - 실제 관계가 비선형인데 선형 모델 사용
     - Feature engineering으로 R² 인위적으로 높일 수 있지만
     - 해석 가능성이나 일반화 성능은 오히려 나빠질 수 있음

  3. **다중공선성**: 
     - 상관관계 높은 feature들을 많이 추가하면 R² 증가
     - 하지만 계수 해석 불가능, 모델 불안정

- **올바른 평가**: R²와 함께 cross-validation 성능, 잔차 분석, 모델 복잡도 등을 종합적으로 고려

### [RAG 기본 - 5문제]

**41번 정답:**
- RAG = Retrieval-Augmented Generation (검색 증강 생성)
- **기본 개념**: 
  - LLM이 답변 생성 시 외부 지식 데이터베이스에서 관련 정보를 먼저 검색(Retrieval)
  - 검색된 정보를 prompt에 추가(Augmentation)
  - 이를 바탕으로 답변 생성(Generation)
  - "모델의 기억력"이 아닌 "실시간 검색"으로 답변

**42번 정답:**
1. **지식 한계(Knowledge Cutoff)**:
   - LLM의 학습 데이터는 특정 시점까지만 존재
   - 최신 정보나 실시간 데이터는 알 수 없음
   - RAG로 최신 문서를 검색하여 해결

2. **Hallucination (환각)**:
   - 모르는 내용에 대해 그럴듯한 거짓 정보 생성
   - RAG로 실제 문서를 기반으로 답변하여 신뢰성 향상

3. **도메인 특화 지식 부족**:
   - 일반적인 LLM은 특정 회사/조직의 내부 정보 모름
   - RAG로 내부 문서를 검색하여 맞춤형 답변

**43번 정답:**
1. **Retrieval (검색)**:
   - 사용자 질의(query)를 받아 관련 문서/정보를 외부 데이터베이스에서 검색
   - Vector similarity, BM25 등의 방법 사용
   - Top-K개의 가장 관련성 높은 문서 추출

2. **Augmentation (증강)**:
   - 검색된 문서들을 사용자 질의와 결합
   - LLM의 입력 prompt를 구성
   - 형식: "다음 정보를 참고하여 답변하시오: [검색된 문서] 질문: [사용자 질의]"

3. **Generation (생성)**:
   - 증강된 prompt를 LLM에 입력
   - 검색된 정보를 바탕으로 최종 답변 생성
   - 출처 인용 포함 가능

**44번 정답:**
- **Vector Database 사용 이유**:
  - 텍스트를 의미 기반 벡터(embedding)로 변환하여 저장
  - 유사도 기반 검색이 가능 (semantic search)

- **단순 키워드 검색 대비 장점**:
  1. **의미 이해**: 
     - 키워드: "자동차 구매" 검색 시 정확히 이 단어가 있어야 검색됨
     - Vector: "차 사는 법", "vehicle buying guide"도 유사하다고 판단하여 검색

  2. **동의어 처리**: 
     - 키워드: "price"와 "cost"를 다른 단어로 취급
     - Vector: 의미적으로 유사하므로 함께 검색

  3. **맥락 이해**: 
     - 키워드: 단어 매칭만
     - Vector: 문장 전체의 의미를 벡터 공간에 표현

  4. **오타 허용**: 
     - Vector embedding은 미세한 차이에 강건

**45번 정답:**
- **문제점**:
  1. **부정확한 답변**: 잘못된 정보를 기반으로 답변 생성
  2. **혼란스러운 출력**: 관련 없는 문서 때문에 초점을 잃음
  3. **Hallucination 악화**: 애매한 정보로 인해 LLM이 추측하여 거짓 정보 생성
  4. **사용자 신뢰 저하**: 출처가 부정확하여 답변 신뢰성 감소

- **개선 방법**:
  1. **Re-ranking (재순위화)**:
     - 검색된 문서를 다시 한번 relevance 점수로 평가
     - Cross-encoder 등 더 정교한 모델 사용
     - Top-K를 더 적은 수로 필터링

  2. **Query 재작성**:
     - 사용자 질의를 더 명확하게 재구성
     - 여러 변형 query로 검색하여 결과 병합
     - 예: "그거 어떻게 해?" → "Python에서 파일을 읽는 방법"

  3. **Hybrid Search**:
     - Vector search + 키워드 search 병합
     - 각각의 장점을 활용하여 recall 향상

  4. **Metadata 필터링**:
     - 문서의 날짜, 카테고리, 출처 등으로 사전 필터링
     - 신뢰할 수 있는 문서만 검색 대상에 포함

  5. **Chunking 전략 개선**:
     - 문서를 너무 작게 나누면 맥락 손실
     - 적절한 크기로 chunk하여 의미 있는 단위 유지

  6. **LLM-based 필터링**:
     - 검색 후 LLM에게 "이 문서가 질문과 관련있는가?" 물어보기
     - 관련 없는 문서 제외
